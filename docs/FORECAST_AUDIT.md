# Forecaster audit

Scope: `backend/flowstate/lab/{sim,forecast,benchmark,health}.py` and the stored dataset. The trained artifact is unchanged. Its sha256 is
`b624154e4e128faa…`, registered in `artifacts/lab/MODEL_MANIFEST.json`, and a test pins it. Everything below is regenerated by `cli benchmark`
(`artifacts/lab/forecast_breakdown.json`).

## Correctness and leakage

| Check | Result |
|---|---|
| Train / validation / test share no seed or episode | Disjoint seed ranges (1000-1011 / 2000-2003 / 3000-3007). A test asserts it from the stored manifest and the row-level episode ids. |
| Held-out scenario | `rush_ramp` appears only in test. |
| Targets use only the future, features only the past | Lag features come from a ring buffer of earlier samples in the same episode. Target rows are dropped when `t+60` falls outside the episode. A test checks the row/target alignment. |
| Hyper-parameters chosen without the test set | Chosen on the validation seeds. |
| Early stopping inside `HistGradientBoosting` | It holds out a random 10% of *training rows*, so rows from one episode sit on both sides. This is mildly optimistic as a stopping signal, but both final models used all 300 iterations, so it never fired and the artifact is unaffected. |
| Capacity ceiling | The grid's best setting (lr 0.1, 63 leaves, 300 iterations) is at the grid edge, so more capacity may help. Not tried, to avoid retraining the verified baseline. |
| Output clipping to `[0, capacity]` | 0.05% of test rows have a true queue above the capacity estimate (maximum 1.07x), so clipping is negligible. |
| Live inference equals offline inference | The flat NumPy evaluation matches scikit-learn to 6e-14 (checked in `health --deep` and golden vectors). |
| Rows within an episode are correlated | Headline uncertainty is now an **episode-clustered bootstrap** (80 test episodes). The MAE gap to persistence is -2.26 to -2.05 vehicles at 30 s and -1.05 to -0.68 at 60 s (95% CI). |

## Findings that matter for integration

1. **The model under-predicts the worst queues** (it regresses to the mean). When the queue later covers at least half the approach, the 30 s forecast is
   6.6 vehicles low on average, and 7.8 low at 60 s. With the 0.5 x capacity rule, spillback recall is only 0.39.
   *Mitigation, validated:* alerting at 0.425 x capacity (30 s) and 0.40 x capacity (60 s), thresholds chosen on validation seeds, raises held-out F1 from
   0.525 to 0.662 at 30 s and from 0.472 to 0.611 at 60 s (persistence: 0.418 and 0.472). The contract uses these rules and attaches their held-out
   precision and recall to every predicted warning. The calibrated upper bound reaches recall 0.95 but precision 0.34, so it is exposed only as
   `possibleSpillback`.
2. **The 60 s forecast loses its edge when an adaptive controller drives traffic.** Test traffic generated under fixed-time signals shows skill 0.42, but under
   the queue heuristic only **0.03** (MAE 2.91 vs 2.99 for persistence). The 30 s forecast holds up (0.54 vs 0.44). A small check on recorded
   ML-controlled replays agrees (30 s skill 0.44, 60 s skill 0.08, 5 episodes). The training data contains only fixed-time and heuristic
   control, so the 60 s horizon should be treated as informational for adaptive controllers until it is retrained on traffic those controllers
   produce. `skillByControlRegime` is in every model status.
3. **Interval coverage is calibrated to the predicted level.** Coverage is 0.90 overall and 0.88-0.93 in every scenario, junction and predicted-occupancy bin, with the
   weakest cells at 0.877 to 0.888 (rush_ramp, junction A1, and predicted at least half full at 60 s). Conditioned on the *true* severity, coverage is lower (0.80-0.83 in
   light and spillback) because that conditioning uses the outcome. This is a known property of the method, and it is why the benchmark reports both.
4. **Forecast-assisted control** (separate from forecast accuracy): no measurable improvement over the plain heuristic on 60 held-out episodes. See
   `INTELLIGENCE_LAB.md`. Better forecasts did not turn into better signal timing with this controller, so stronger controllers should consume the
   `predicted` block, with its intervals and alert rules, rather than the lab's `ForecastAware` rule.

## Performance (`cli profile`, `artifacts/lab/performance.json`)

Measured on the development machine, which was at **about 100% CPU from other applications during profiling**, so wall-clock figures are inflated several-fold
(the same SUMO step costs 1-3 ms when the machine is idle). CPU-time microbenchmarks at 400+ vehicles in the network are the contention-independent figures:
TrafficState collection about 0.6-0.8 ms CPU, forecast inference about 10-11 ms CPU per 16-approach decision, controller decision under 0.2 ms. Building the report took about 1-5 ms wall (contended), and
the report JSON is about 10 KB per 5 s of simulated time. Resident memory in the profile process is about 155-165 MB, growing about 6-9 MB over a 1,200 s run (it holds every
frame for replay). With stress demand (1.4x) the network peaked at 526 vehicles. The profile includes the loaded model (flat trees plus
scikit-learn) in one process.
